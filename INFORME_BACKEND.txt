2. CONTROLLER DE EVALUATION PLAN (HITOS/PLANES)
================================================================================

Archivo: controllers/EvaluationPlanController.java

Clase:
    @RestController
    @RequestMapping("/api/evaluation-plans")
    @CrossOrigin(origins = "*")
    public class EvaluationPlanController

Métodos principales:

    a) GET /api/evaluation-plans/subject/{subjectId}
       - Obtiene el plan de evaluación de una materia
       - Requiere: JWT Token + ROLE_TEACHER
       - Devuelve: EvaluationPlanResponse con lista de componentes

    b) POST /api/evaluation-plans/subject/{subjectId}
       - Crea un nuevo plan de evaluación
       - Requiere: JWT Token + ROLE_TEACHER
       - Si ya existe, retorna el existente
       - Devuelve: EvaluationPlanResponse vacío (sin componentes)

    c) POST /api/evaluation-plans/subject/{subjectId}/activate
       - Activa el plan de evaluación
       - Requiere: JWT Token + ROLE_TEACHER
       - Valida que componentes sumen exactamente 100%
       - Devuelve: Mensaje de éxito

4. CONFIGURACIÓN DE SEGURIDAD
================================================================================

Archivo: config/SecurityConfig.java

Configuración CORS:
    - Orígenes permitidos:
      * http://localhost:4200
      * http://localhost:4201
    - Métodos: GET, POST, PUT, DELETE, PATCH, OPTIONS
    - Headers: Todos (*)
    - Credenciales: Habilitadas

Configuración de Autenticación:
    - Sesiones: DESHABILITADAS (Stateless con JWT)
    - CSRF: DESHABILITADO (API REST sin sesiones)
    - Endpoints públicos:
      * /api/auth/login
      * /api/auth/logout
      * Todas las requests OPTIONS (CORS preflight)
    - Endpoints restringidos:
      * /api/users/** → ADMIN only
      * Todo lo demás → Requiere autenticación

Filtro JWT (JwtAuthFilter.java):
    - Extrae el token del header: Authorization: Bearer <token>
    - Valida el token usando JwtService
    - Carga el usuario en SecurityContextHolder
    - Si el token es inválido, permite que continúe (sin autenticación)
    - El @PreAuthorize en los métodos rechaza sin autenticación

Roles Disponibles (SecurityAuthorities.java):
    ROLE_ADMIN    → Acceso total
    ROLE_TEACHER  → Acceso a endpoints de docente
    ROLE_STUDENT  → Acceso a endpoints de estudiante

6. MODELOS Y DTOS
================================================================================

EvaluationPlanResponse.java:
    public record EvaluationPlanResponse(
        Integer id,
        Integer subjectId,
        List<ComponentResponse> components
    )

    Descripción:
    - id: Identificador del plan (generado por BD)
    - subjectId: ID de la materia asociada
    - components: Lista de componentes de evaluación

ComponentResponse.java:
    public record ComponentResponse(
        Integer id,
        String name,
        BigDecimal weight,
        String description
    )

    Descripción:
    - id: Identificador del componente
    - name: Nombre (ej: "Parcial 1", "Tareas", etc.)
    - weight: Ponderación en porcentaje (0-100)
    - description: Descripción del componente

EvaluationPlan (Entidad JPA):
    - id: Clave primaria
    - subject: Relación con Subject
    - components: Lista de componentes
    - status: Estado del plan (ACTIVE, INACTIVE)

Component (Entidad JPA):
    - id: Clave primaria
    - evaluationPlan: Relación con plan
    - name: Nombre del componente
    - weight: Ponderación
    - description: Descripción

7. SERVICE (EVALUATIONPLANSERVICE)
================================================================================

Archivo: services/EvaluationPlanService.java

Métodos:

1. getBySubject(Integer subjectId, String teacherEmail)
   - Obtiene un plan existente
   - Valida que el docente sea propietario de la materia
   - Lanza ResourceNotFoundException si no existe
   - Retorna: EvaluationPlanResponse

2. createForSubject(Integer subjectId, String teacherEmail)
   - Crea un nuevo plan vacío
   - Si ya existe, retorna el existente
   - Valida autorización del docente
   - Retorna: EvaluationPlanResponse con lista vacía

3. activatePlan(Integer subjectId, String teacherEmail)
   - Activa un plan existente
   - Valida que tenga al menos un componente
   - Valida que componentes sumen exactamente 100%
   - Cambia estado de la materia a ACTIVE
   - Lanza InvalidOperationException si validación falla

Excepciones manejadas:
    - ResourceNotFoundException: Cuando no existe materia o plan
    - UnauthorizedAccessException: Cuando docente no es propietario
    - InvalidOperationException: Cuando validaciones fallan

Transacciones:
    - getBySubject: readOnly=true (consulta)
    - createForSubject: readOnly=false (modifica BD)
    - activatePlan: readOnly=false (modifica BD)

10. SOLUCIÓN DE ERRORES COMUNES
================================================================================

ERROR: 401 Unauthorized
    Causa: Token no enviado o inválido
    Solución:
    1. Verificar que Authorization header esté presente
    2. Formato correcto: "Authorization: Bearer <token>"
    3. Verificar token en jwt.io para validez
    4. Si expiró, hacer login nuevamente
    5. Revisar JWT_SECRET_KEY en environment

ERROR: 403 Forbidden
    Causa: User no tiene el rol requerido
    Solución:
    1. Verificar que el usuario tenga ROLE_TEACHER
    2. Revisar tabla de usuarios en BD
    3. Verificar que el JWT decodificado contenga el rol correcto
    4. Consultar con admin para asignar rol

ERROR: 404 Not Found (Materia no existe)
    Causa: El subjectId no existe en BD
    Solución:
    1. Verificar que subjectId sea válido
    2. Hacer GET /api/subjects para listar materias disponibles
    3. Verificar con docente cuál es su materia
    4. Crear la materia si no existe

ERROR: 404 Not Found (Plan no existe)
    Causa: No se ha creado el plan para esa materia
    Solución:
    1. Hacer POST a /evaluation-plans/subject/{subjectId} primero
    2. Luego hacer GET para obtenerlo
    3. Crear los componentes del plan
    4. Finalmente activar con /activate

ERROR: 400 Bad Request (Ponderaciones incorrectas)
    Causa: Componentes no suman exactamente 100%
    Solución:
    1. Sumar todas las ponderaciones (weight) de componentes
    2. Deben sumar exactamente 100.00
    3. Si suman 99.99 o 100.01, ajustar
    4. Usar BigDecimal para evitar errores de precisión

ERROR: 400 Bad Request (Plan sin componentes)
    Causa: Intenta activar plan vacío
    Solución:
    1. Crear al menos un componente
    2. Los componentes se agregan en endpoint separado
    3. Ir a /evaluation-plans/subject/{subjectId}/components
    4. Agregar componentes con ponderaciones que sumen 100%
    5. Luego activar

CORS ERROR (Frontend)
    Error: Access to XMLHttpRequest blocked by CORS
    Causa: Frontend en puerto distinto a 4200/4201
    Solución:
    1. Verificar que frontend corre en 4200 o 4201
    2. Si usa otro puerto, agregar en SecurityConfig:
       corsConfiguration.setAllowedOrigins(java.util.List.of(
           "http://localhost:PUERTO"
       ));
    3. Redeploy del backend

TOKEN EXPIRADO
    Manifestación: 401 Unauthorized aunque token esté en header
    Solución:
    1. Tokens duran 24 horas (86400000 ms)
    2. Si la sesión lleva más de 24h, hacer logout/login
    3. Guardar nuevo token
    4. Usar nuevo token en requests

CONEXIÓN A BD FALLIDA
    Error: Connection refused / Timeout / Unknown host
    Solución:
    1. Verificar que PostgreSQL esté corriendo
    2. Verificar credenciales en environment:
       - DB_URL debe ser accesible
       - DB_USERNAME correcto
       - DB_PASSWORD correcto
    3. Probar conexión con: psql -h <host> -U <user> -d <database>
    4. Revisar firewall/networking
