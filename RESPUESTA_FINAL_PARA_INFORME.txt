¿CUÁL ES EL FORMATO CORRECTO DEL ENDPOINT?

✅ RESPUESTA CORRECTA:
   
   POST /api/evaluation-plans/subject/{subjectId}
   
   Con BODY VACÍO (sin contenido JSON)
   
   Ejemplo:
   POST http://localhost:8080/api/evaluation-plans/subject/5
   Authorization: Bearer eyJhbGciOi...
   Content-Type: application/json
   
   Body: (VACÍO - no enviar nada)

❌ RESPUESTA INCORRECTA:

   POST /api/evaluation-plans
   
   Con body { subjectId, name, weight }
   
   Esto no funciona porque no existe ese endpoint.

================================================================================
POR QUÉ EL BODY DEBE ESTAR VACÍO
================================================================================

Razón 1: Sintaxis del Controller
    @PostMapping("/subject/{subjectId}")
    public ResponseEntity<ApiResponse<EvaluationPlanResponse>> createForSubject(
        @PathVariable Integer subjectId,          ← El ID va en la URL
        Authentication authentication             ← Se obtiene automáticamente
    )
    
    → NO hay @RequestBody
    → El método NO espera parámetros adicionales

Razón 2: El Plan se Crea Vacío
    EvaluationPlan newPlan = evaluationPlanRepository.save(
        EvaluationPlan.builder()
            .subject(subject)
            .build()
    );
    
    → El plan se crea sin componentes inicialmente
    → Los componentes se agregan después en otro endpoint

Razón 3: Validación del Service
    El servicio validateSubjectAndTeacher() solo requiere:
    - subjectId (en URL)
    - teacherEmail (del JWT token)
    
    → No necesita name, weight, description, etc.

async function login(email, password) {

async function createEvaluationPlan(subjectId, token) {
  const response = await fetch(
    `http://localhost:8080/api/evaluation-plans/subject/${subjectId}`,
    {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      }
      // ⚠️ NO enviar body aquí
    }
  );
  
  if (response.status === 201) {
    const data = await response.json();
    console.log('Plan creado:', data.data);
    return data.data;
  } else {
    console.error('Error:', response.status);

  }
}

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';

@Injectable({

  private apiUrl = 'http://localhost:8080/api';

  // Crear plan
  createEvaluationPlan(subjectId: number, token: string) {
    const headers = {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    };
    
    // ⚠️ NO enviar body - dejar undefined o null
    return this.http.post(
      `${this.apiUrl}/evaluation-plans/subject/${subjectId}`,
      null, // ← Body VACÍO
      { headers }
    );
  }

  // Obtener plan
  getEvaluationPlan(subjectId: number, token: string) {
    const headers = {
      'Authorization': `Bearer ${token}`,
      'Content-Type': 'application/json'
    };
    
    return this.http.get(
      `${this.apiUrl}/evaluation-plans/subject/${subjectId}`,
      { headers }
    );
  }
}

ERRORES COMUNES Y SOLUCIONES
================================================================================

ERROR: 401 Unauthorized
CAUSA: Token inválido, expirado o no enviado
SOLUCIÓN:
  1. Verificar que el header Authorization esté presente
  2. Formato correcto: "Authorization: Bearer <token>"
  3. Obtener nuevo token si expiró (duran 24 horas)
  4. Verificar que el email/password sean correctos

---

ERROR: 403 Forbidden
CAUSA: 
  A) Usuario no tiene ROLE_TEACHER
  B) Usuario no es propietario de la materia
SOLUCIÓN:
  1. Verificar rol del usuario en BD: SELECT * FROM users WHERE email='...';
  2. Verificar que sea profesor de la materia
  3. Contactar a administrador para asignar rol

---

ERROR: 404 Not Found
CAUSA: La materia (subjectId) no existe
SOLUCIÓN:
  1. Verificar que subjectId sea válido: SELECT * FROM subjects;
  2. Usar el ID correcto de la materia
  3. Crear la materia si no existe

---

ERROR: Mensaje "No tienes permisos para acceder al plan de esta materia"
CAUSA: El docente no es propietario de esa materia
SOLUCIÓN:
  1. Asignar la materia al docente en BD
  2. O cambiar el docente de la materia
  3. Consultar con administrador

---

ERROR: CORS error en consola del navegador
CAUSA: Frontend en puerto distinto a 4200/4201
SOLUCIÓN:
  1. Asegurarse que frontend corre en localhost:4200 o 4201
  2. Si usa otro puerto, comunicar al equipo backend
  3. Solicitar que agreguen el puerto en SecurityConfig

---

ERROR: Body JSON en POST cuando debería estar vacío
CAUSA: Envío innecesario de { subjectId, name, weight }
SOLUCIÓN:
  1. NO enviar body
  2. El subjectId va en la URL: /subject/{subjectId}
  3. Dejar body = null o undefined
  4. Solo Content-Type: application/json
